How to Find Every Deal in Your monday.com CRM Where the Deal Size Has Never Been Updated Since It Was Created

📅 October 11, 2026 ✍️ agent7d Team ⏱ 5 min read

The estimate a rep types at deal creation is not a deal value. It's a placeholder. The problem is that most monday.com pipelines treat it like gospel — and by the time you're forecasting off it, you're forecasting off a guess that's three months old.

The Problem

Here's how it plays out: a rep logs a new opportunity. They're excited. They type a number — maybe from a rough conversation, maybe from a similar deal they closed last quarter, maybe from intuition. That number lands in the Deal Value column and almost never moves again.

Meanwhile, the deal progresses. There are scoping calls. A product demo. A proposal. The scope shifts. The budget changes. The stakeholder changes. And the value column? Still says $45,000. Same as day one.

The result is a pipeline coverage ratio built on phantom revenue. Your forecast shows $1.2M in weighted pipeline. But if 30% of those deal values were set during the first conversation and never revisited, you don't actually know what you have. You have a spreadsheet that looks confident and a forecast that isn't.

This isn't a discipline problem. It's a structural problem. monday.com doesn't have a native mechanism that alerts anyone when a value field hasn't been touched in 60 days. Reps don't update values because nothing prompts them to. Managers don't catch it because they're reviewing stage movement, not field-level change history. The frozen value just sits there, silently distorting every number downstream.

The Solution

You need to surface every open deal where the value column hasn't changed since the item was created — and then sort those deals by age, so you know which ones are most dangerous to your forecast.

monday.com stores creation dates natively on every item. Combined with automation logs, column activity, and some deliberate view construction, you can build a system that flags value-frozen deals before your next pipeline review. The goal is not to punish reps. It's to separate deals with legitimately stable values from deals where nobody has thought about the number since the opening conversation.

Step by Step

1. Add a "Value Last Updated" date column to your deals board.

This won't backfill historical data, but from this point forward, use an automation: When the Deal Value column changes → set Value Last Updated to today. This creates your tracking layer.

2. Add a formula column that calculates days since value was updated.

Use TODAY() - {Value Last Updated}. For deals that predate your automation, the Value Last Updated column will be blank — those are your highest-priority suspects.

3. Build a filtered view called "Frozen Values."

Filter criteria: Status is not Closed/Won/Lost AND (Value Last Updated is blank OR Days Since Value Updated is greater than 45). Sort by deal creation date, oldest first.

4. Cross-reference with stage activity.

A deal with a 90-day-old value sitting in Proposal stage is different from a deal with a 90-day-old value sitting in Prospecting. Add Stage as a column in your view so you can triage at a glance.

5. Add a "Value Review Status" dropdown column.

Options: Needs Review, Confirmed Accurate, Updated, Stale/No Response. This gives your team a way to work through the list without losing context between sessions.

Real Example

A RevOps lead at a B2B services firm ran a pipeline review using this exact approach. Out of 67 open deals, 21 — roughly 30% — still carried the exact dollar value entered at creation. Some of those deals had been through three rounds of scoping conversations. One had a signed NDA and a revised SOW sitting in email. The value column still said $28,000, entered nine months earlier. The actual expected contract value based on the revised scope was closer to $74,000.

That single deal was being weighted at 60% probability in the forecast — which meant it was contributing $16,800 to the forecast instead of $44,400. Multiply that distortion across 21 deals and you start to understand why pipeline reviews feel unreliable even when stage data looks clean.

The fix wasn't complicated. It was a two-hour review session, a clear protocol for when reps must update deal value (after every scoping conversation, after any change in scope or budget), and a weekly automation reminder for deals where the value column hasn't moved in 30 days.

How to Get Started

Run the Frozen Values view before your next pipeline review. If you find more than 15% of your open deals have unchanged values from creation, your forecast is structurally unreliable — not because your reps are careless, but because the pipeline was never set up to catch this.

Categorize every frozen deal into one of three buckets: Correct (value was always accurate, confirm and document it), Update (value needs to reflect current scope), or Escalate (deal has gone quiet and the value is the least of your problems). Work the list from oldest to newest.

The goal is a pipeline where every open deal value reflects your best current understanding — not the optimism of the first call.
